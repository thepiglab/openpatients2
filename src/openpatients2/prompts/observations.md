Extract clinically usable measurements and test findings: laboratories, vitals, imaging, pathology, microbiology, and physiological tests.

Preserve the exact test name, value, comparator (<, <=, >, >=, =), unit, specimen, method, site, reference interval, and time when reported. Do not drop normal quantitative laboratory values merely because they are normal: they may define an eligibility threshold or baseline. Do not invent a laboratory result from 'labs were normal'. Record a relevant qualitative finding when explicitly stated. Do not infer abnormality from outside reference ranges; flag=high/low/normal requires wording or an explicit source-provided interval supporting the classification. Leave flag=unknown otherwise.

Test status and result polarity are separate. 'HIV test negative' is assertion=present, status=resulted, flag=negative. 'No HIV test was performed' is status=not_performed. 'CT ordered to exclude embolism' is an ordered test, NOT a negative result or confirmed embolism. Pending cultures do not establish an organism. A false-positive test described in the source must retain that interpretation.

Treatment goals, titration targets and desired therapeutic ranges are NOT measured test results. For example, 'titrate anticoagulation to assay goal X–Y' does not document an assay result of X–Y. Do not create an observation for the target alone, or mark it resulted. Such targets belong in the medication regimen or monitoring plan, extracted by separate tasks. Retain all actual measured findings and explicitly documented performed tests, including repeated findings at distinct times.

Keep repeated values at different times as separate items. Never average, select the most abnormal, convert units, infer eGFR/creatinine clearance, calculate scores, or use a publication date as a sample date. Preserve '<0.01' rather than replacing it with zero. Use text_value when a number or range cannot be safely represented. Distinguish absolute and percentage counts, plasma/serum/urine specimens, and oxygen settings during a blood gas when written.

For measurements in a table, preserve the time from the row-group heading (for example On admission versus At 48 h), not merely a general table caption that mentions both times. Include an additional exact quotation of that heading from the SAME table-row segment in the item's evidence so time.text occurs literally in its evidence. Keep the exact data-row quotation as well. Do not concatenate noncontiguous excerpts into a fabricated quotation. Do not erase a documented time to satisfy validation. Keep each patient's column and each time point distinct. For narrative findings, add a separate exact time quotation from that patient's corresponding event when needed.

Pathology findings and molecular tests belong here when stated; the oncology task adds tumor-specific links. Negative margins do not mean no cancer. Do not transform an imaging impression ('suspicious for malignancy') into a confirmed diagnosis. Evidence should bind the value to the correct test and patient, not merely match the number somewhere in the record.


DECISION EXAMPLES AND NEGATIVE CONTROLS
Positive result: "HIV test negative" is an affirmed resulted observation with flag=negative, text_value preserving negative, result_absent_reason=null. Explicit nonperformance: "Biopsy was not performed" uses status=not_performed, no result, result_absent_reason=not_performed; it is NOT a negative biopsy. Pending: "Culture pending" has status=pending, text_value=null, numeric_value=null, flag=unknown, result_absent_reason=pending. Missing: no creatinine mention produces no creatinine item, not 0 or normal. A named test with an unstated result uses result_absent_reason=not_reported, not inferred normality. Keep a test result separate from a diagnosis; a negative test is not universal exclusion of the disease. Do not infer high/low from external reference ranges. Preserve < and > instead of turning thresholds into exact values.

An example in these instructions is not patient evidence. Populate only claims supported by the supplied record. Empty output is a valid, preferred answer when the task has no supported facts.
