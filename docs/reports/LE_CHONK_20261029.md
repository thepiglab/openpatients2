## Root cause and code correction

The pinned checkpoint is `mistralai/Mistral-Large-4-1T-A52B-NVFP4`, revision
`d5fdac874617651e8dac18fe8609075700ce8c93`. It uses native `params.json`.
Both CPU checkpoint validation and runtime inventory already knew that, and the
serving arguments already selected `--config-format mistral --load-format mistral`.
The shared `ServerGroup.preflight` still unconditionally required `config.json`.
Its generic error mentioned the SIF too, but the downloaded SIF was present.

Changes:

- Pass an explicit pinned configuration filename through `ServingConfig`.
  Mistral requires `params.json`; existing profiles still require `config.json`.
  Do not create a fake Hugging Face config or weaken snapshot identity checks.
- Share the artifact gate between CPU download and GPU startup. The CPU job must
  pass it before publishing ready receipts and releasing a successful dependency.
- Record worker exceptions with their type, message and failure phase. Previously
  this startup exception left a misleading `interrupted` receipt; cancellation
  still retains that status.
- Reset inherited Beam competition mode in the Mistral launcher so it cannot
  accidentally select the Beam-only competition experiment.

Validation: 99 tests passed across Mistral, Super download/launch, worker lifecycle,
packing, prior runtime regressions and Beam competition tests. Tests cover native
parameters, missing config/SIF/snapshot, mismatched snapshot identity, unchanged
default config requirements, CPU refusal before readiness, startup-error receipts
and cancellation cleanup. Shell syntax and git whitespace checks also passed.
These are local tests, not a claim that this model has run on hardware.
