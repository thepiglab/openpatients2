# Dense clinical reference corpus

One continuing corpus of purposefully varied PMC case reports (a challenge set, not a random sample of
PMC), currently 1,250 articles from two selection rounds: the original 500 (24 clinical/species strata)
and 750 permissive-licensed, gap-targeted and data-rich articles (36 lanes). Rounds, lanes, licenses
and splits are fields in `selection.json`, not folders; see [SELECTION.md](SELECTION.md). AI reference
annotations, not physician-adjudicated gold: model annotators read the original article text, a parent
reviewer re-reads every final annotation against its source, and only signed receipts count as review.
A selected or drafted article is not a completed annotation.

The tracker is `data/dense_clinical_cases_v1/article_checklist.json`, regenerated by `op2 dense export`:
one entry per article with a `completed` flag, the individual review checks and the remaining work.

## What is in this folder

Data and docs only. All code is in the package `src/openpatients2/dense/` (paths: `openpatients2.dense_store`).

```
benchmarks/dense/
  README.md                       this map
  ANNOTATION_PROTOCOL.md          annotation rules (shared-rules block generated from rules/annotation_rules.yaml)
  SUPPLEMENT_DOCUMENT_REVIEW.md   PDF/ZIP/DOCX supplement review protocol
  SELECTION.md, selection.json    selection rounds, splits; one row per article (round, stratum/lane, split, license)
  acquisition/                    acquisition log (decisions.json, network.json) and round-1 screening records
  article_theme_features.json     journal/keywords/affiliations per article from raw XML, for viewer themes
  claude_prompts/                 agent briefs (annotator, parent reviewer, re-sign, backfill, lessons)
  articles/<ID>/
    source.json                     parsed article (segments, figures, supplements, hashes)
    source.txt, raw.xml             readable text / original JATS            [cache, gitignored]
    annotation_draft.json           annotator's working annotation
    annotation.json                 parent-promoted canonical annotation
    schema_target.draft.json        materialized runtime contracts           [cache, gitignored]
    schema_target.json              reviewed full patient-bundle target
    figure_assets.json              downloaded image hashes/paths (pixels live in data/.dense-figure-cache)
    visual.json                     pixel-reviewed figure analysis
    figure_ehr_labels(.draft).json  EHR category/includability per panel     [.draft = cache]
    figure_privacy_flags(.draft).json  burned-in text / face / anatomy flags [.draft = cache]
    measurement_series(.draft).json serial numeric tables                    [.draft = cache]
    needs_review.json               open judgment items from `op2 dense normalize`
    video_inspection.<FID>.<role>.json  sampled video-frame inspection records
    supplements/
      assets.json                   acquisition record (bytes in data/.dense-supplement-cache)
      manifest(.draft).json         per-file content manifest                [.draft = cache]
      <SID>.visual.json             image supplement review target
      <SID>.figure_assets.json      image supplement acquisition record (pilot articles)
      <SID>.document(.draft).json   PDF/ZIP/DOCX supplement review target    [.draft = cache]
      <SID>.archive_members.json    extracted ZIP member record              [cache]
    receipts/
      annotation.parent.json        parent source review (openpatients2.dense.review_record.save_review)
      schema|visual|figure-ehr|figure-privacy|measurement-series|supplement-manifest.<agent|parent>.json
      supplement.<SID>.<agent|parent>.json
```

Store kinds keep the old folder names (`sources`, `drafts`, `annotations`, `schema-submissions`, ...), so
`--folder drafts|annotations` and receipt fields such as `annotation_folder: "annotations"` keep their meaning.
Free-text notes inside signed files may quote old paths; they are content (bound by hashes), not links.

## Running the tools

`op2 dense <tool> [args]` (same as `python -m openpatients2.dense.<tool>`; `op2 dense --help` lists them,
`op2 dense <tool> --help` shows options). Run from anywhere: default roots and caches resolve from the
repository checkout. `R` below is `benchmarks/dense` (the default wherever a tool takes an optional root).
**A `--role` call is a signature: validate by running the same command without `--role`.**

| step | command | writes | reads |
|---|---|---|---|
| 1 acquire | `op2 dense acquire acquire --selection-file F --round N [--permissive-only]` (SELECTION.md) | `source.json`, `source.txt`, `raw.xml`, `selection.json` rows | PMC |
| 2 annotate | annotator (claude_prompts/ANNOTATOR_BRIEF.md); check with `op2 dense validate R --folder drafts` | `annotation_draft.json` | `source.json` |
| 3 figures | `op2 dense figure_assets R --article ID` | `figure_assets.json` | `source.json` |
| 4 visual review | annotator writes `visual.json`; `op2 dense visual_review R --article ID` | `receipts/visual.*.json` | visual, source, annotation, figure assets |
| 5 schema | `op2 dense schema_targets R --folder drafts\|annotations --article ID` | `schema_target.draft.json` (copy to `schema_target.json`) | annotation, source |
| 6 schema review | `op2 dense schema_review R --folder ... --article ID` | `receipts/schema.*.json` | annotation, schema target, source |
| 7 parent source review | `openpatients2.dense.review_record.save_review` | `annotation.json`, `receipts/annotation.parent.json` | draft, source |
| 8 supplements | `op2 dense supplement_assets acquire\|peek\|extract\|extract-text\|status\|cleanup`, `op2 dense supplement_manifest_review`, `op2 dense supplement_review R --article ID --supplement SID` | `supplements/*`, `receipts/supplement-manifest.*`, `receipts/supplement.SID.*` | source, annotation, cache |
| 8b videos | `op2 dense video_frames R --article ID [--list] [--video FILE] [--every S] [--max-frames N] [--cleanup]` | frames in `data/.dense-figure-cache/ID/video-*` (reviewer writes `video_inspection.<FID>.<role>.json`) | `source.json`, PMC |
| 9 EHR sidecars | `op2 dense figure_ehr_review`, `figure_privacy_review`, `measurement_series_review` (`R --article ID [--draft]`) | `figure_ehr_labels`, `figure_privacy_flags`, `measurement_series` + receipts | visual, source, annotation, supplements |
| 10 normalize | `op2 dense normalize [--article ID ...] [--apply]` after any annotation edit | annotation fixes, `needs_review.json`, schema targets | annotation, source |
| 11 gates | `op2 dense reference_gates R --article ID [--folder annotations]` | (report) | everything above |
| 12 release | `op2 dense export` | `data/dense_clinical_cases_v1/` | the whole corpus |

Videos: a source-listed PMC MP4 (figure media such as `VID1`, a supplement asset, or an `unassigned_media` video) is
obtainable, not "unavailable". `op2 dense video_frames` downloads it into the shared figure cache (same lock and 1 GB
cap as `figure_assets`, per-file cap as `supplement_assets`), verifies the source MD5, probes it with `ffprobe` and
samples full-resolution PNG frames with the system `ffmpeg` at fixed timestamps across the whole duration, printing
paths, timestamps, hashes and a `video_inspection_template`. Reviewers view every frame and record a video figure as
`video_inspection.<FID>.agent.json` / `.parent.json` (the image-only `visual.json` row stays `unavailable`); a video
supplement is reviewed in the supplement manifest (`manifest_video_frames_sampled`). Procedure: "Videos" in
`claude_prompts/ANNOTATOR_BRIEF.md` and `PARENT_REVIEWER_BRIEF.md`. The parent frees the cache with `--cleanup`.

`op2 dense scan_glued_text [--root R]` is a read-only report of glued words. `op2 viewer` reads `source.json`,
`annotation.json`, `schema_target.json`, `visual.json` and their receipts live. After acquiring articles, refresh
the theme table with `op2 viewer --write-theme-features` (raw XML is gitignored; the Pages build reads the table).

Receipts bind content hashes only (annotation, target, source text), never paths, so an article folder can move
between roots without re-signing.
